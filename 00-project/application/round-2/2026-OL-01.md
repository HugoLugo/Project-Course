# Simulation of Warehouse Robot Coordination

## My interpretation of the brief
The project is about building a 2D warehouse simulation where multiple robots move around, transport goods, and coordinate with each other to avoid collisions and complete tasks efficiently. The user can define the layout, place obstacles, set up robots and target points, and then watch the simulation run. The main challenge is not the graphics but the coordination: how robots plan routes, how they avoid each other, and how tasks get assigned. At least two different path-planning or coordination strategies need to be implemented and compared using measurable results like total service time, distance travelled, and waiting time. A real robot or a full warehouse management system is outside scope.

## Why I am a good fit for this project
I am interested in systems where simple local decisions produce complex behaviour, and I enjoy thinking about algorithms that have a visible effect. Warehouse coordination sits at a nice intersection of path planning, scheduling, and simulation, and I like that the results are measurable rather than subjective. I want to understand how different coordination strategies trade off efficiency, scalability, and simplicity. I also enjoy the visual side, being able to watch the simulation and see why one strategy performs better than another makes the work more concrete and easier to reason about.

## Proposed approach
This project is more about the system than about a user interface, so I would start by defining what the simulation actually is and what it needs to produce. The goal is an experimental environment where different coordination strategies can be run under the same conditions and compared honestly, which means the simulation logic has to be clean, measurable, and separate from the visualisation.

The core questions I need to answer first are about the model: what a warehouse looks like, how robots and tasks are represented, and what "time" means in the simulation. From there, the hard part is coordination how robots plan routes, how conflicts are detected when two robots want the same space, and how those conflicts get resolved. I don't have all the answers yet, and that's fine. What matters is that the first strategy is simple enough to build and measure, so a second strategy can be compared against it fairly using the same metrics and scenarios.

## Initial plan
1. Define the warehouse model: grid, obstacles, robots, tasks, and how time advances.
2. Implement a first path-planning method and get robots moving and completing tasks.
3. Add conflict detection and a simple coordination rule so robots do not collide.
4. Measure service time, distance travelled, and waiting time.
5. Implement a second coordination or path-planning strategy.
6. Compare the two strategies under the same scenarios and document the trade-offs.
7. Build the visual simulation so the behaviour is observable.
8. Add tests for the core algorithms and write up what I learned and where the limits are.
